# 发货与订单状态查询

intentCode: `order.query.fulfillment`

route: MCP `order_query`, `queryType=fulfillment`

## 适用问题

用于用户查询具体订单是否付款、是否发货、发货延迟原因、订单取消、订单明细状态。

典型问题：

- 订单为什么还没发货？
- 我这个订单状态是什么？
- 付款成功了吗？
- 订单取消了吗？
- 商品是不是缺货？

## 必要槽位

优先需要：

- 订单号。
- 用户身份或登录态。

可选：

- 商品名称。
- 支付流水号。
- 下单时间。

## 路由动作

调用 MCP 工具：

```json
{
  "tool": "order_query",
  "queryType": "fulfillment",
  "orderId": "<order_id>"
}
```

## 回答口径

按订单状态回答：

- 待支付：提示支付剩余时间、支付入口和超时关闭风险。
- 已支付待发货：说明预计发货时间或延迟原因。
- 已发货：转物流状态查询。
- 已完成：说明已签收或交易完成时间。
- 已取消：说明取消原因、退款状态或是否可重新下单。
- 缺货或异常：说明补发、换货、退款或转人工处理路径。

## 延迟发货处理

1. 先查询商品是否预售、定制、大促延迟或仓库异常。
2. 告知用户当前订单节点和预计处理时间。
3. 若超过承诺时效，按平台规则提供催发货、取消订单、补偿或转人工选项。

## 不应做的事

- 不承诺库存一定有货。
- 不在未查询支付系统时确认付款成功。
- 不把具体订单状态问题只用知识库规则回答。
